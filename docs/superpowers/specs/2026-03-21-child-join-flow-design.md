# Child Join Flow — Design Spec

**Goal:** Allow a child to join an existing family from the setup wizard by entering an invite code, then selecting their profile from the family's member list.

**Date:** 2026-03-21

---

## Context

The app already has an invite/join system in `JoinFamily.jsx` used from Settings. The wizard Step 3 for child role currently shows a static placeholder message. This feature connects the two: children can join a family during first-time setup.

The invite code is generated by the parent from Settings → "Collega dispositivi" → "Invita". It does not expire; the parent can regenerate it manually.

## User Flow

### Parent side (already exists)

1. Settings → "Collega dispositivi" → "Invita"
2. Generates 6-char code from charset `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no I, O, 0, 1 to avoid confusion)
3. Shares code with child (voice, message, etc.)

### Child side (to build)

1. Opens app → Wizard Step 1 (welcome) → Step 2 selects "Figlio/a" and enters name
2. **Step 3**: sees invite code input (6-char field, uppercase, charset-restricted)
3. Enters code → app calls `joinFamilyByCode(code)` from `sync.js`
4. On success: shows list of child members in the family with their icons
5. Child selects "Sono io" on their profile
6. Wizard completes immediately → navigates to `/login`

## Components Modified

### `WizardStep3.jsx`

The `if (isChild)` branch (lines 17–37) is replaced with a two-phase UI:

**Phase 1 — Code Entry:**
- 6-character text input (auto-uppercase, restricted to charset `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`)
- "Unisciti" button to submit
- Loading spinner during API call
- Error messages: invalid code, offline, no children found

**Phase 2 — Member Selection:**
- Grid of child members (icon + name) filtered by `role === 'child'`
- Tap to select → highlight
- "Conferma" button to proceed
- Calls `onNext({ familyId: family.id, selectedMember: mappedMember })` where `mappedMember` is shaped as `{ id, name, role, access_level, icon, color }`

**Important:** The selected member must be mapped from the raw Supabase record to the authStore shape `{ id, name, role, access_level, icon, color }` — stripping internal fields like `_deleted`, `_version`, `_device_id`, `family_id`, `pin_hash`, `updated_at`.

### `SetupWizard.jsx`

Add a new handler `handleChildJoinComplete({ familyId, selectedMember })`:
- Calls `authStore.setFamily(familyId)` — note: `familyId` is `family.id` (a string UUID), NOT the full family object
- Calls `authStore.setMember(selectedMember)` — already mapped to correct shape
- Calls `authStore.completeSetup()`
- Navigates to `/login`

Step 3's `onNext` prop: when `data.ownerRole === 'child'`, pass `handleChildJoinComplete` instead of `goNext`.

## Data Flow

```
Child enters code
  → joinFamilyByCode(code)           [sync.js, already exists]
    → Supabase query: families.invite_code = code
    → Downloads family + members to local Dexie
    → Returns family object (full row)
  → WizardStep3 reads members from local Dexie (already saved by joinFamilyByCode)
  → Filter members where role === 'child'
  → Show selection UI
  → Child picks their profile
  → Map member to { id, name, role, access_level, icon, color }
  → onNext({ familyId: family.id, selectedMember })
  → SetupWizard.handleChildJoinComplete finalizes auth state
  → Navigate to /login
```

## Encrypted Sync Handling

`joinFamilyByCode(code)` accepts optional `pin` and `syncSecret` params for encrypted families. For the wizard child flow, we call it **without** these params. This means:

- **Unencrypted families:** Members are stored in plain text — works perfectly.
- **Encrypted families:** Member names/fields stored encrypted in Supabase will remain encrypted in local Dexie. The member selection grid would show garbled data.

**Decision:** For R1, the child wizard join flow supports **unencrypted families only**. This is acceptable because:
- Encrypted sync is an opt-in feature configured by advanced users
- The Settings → "Unisciti" flow in `JoinFamily.jsx` already handles the encrypted case (it has PIN + secret fields)
- We add a clear error message if members appear encrypted: "Questa famiglia usa la sincronizzazione crittografata. Chiedi al genitore di aggiungerti dalle Impostazioni."

## Edge Cases

| Scenario | Behavior |
|----------|----------|
| Invalid code | "Codice non valido. Controlla e riprova." |
| Network error / offline | "Serve una connessione internet per unirti alla famiglia." |
| No children in family | "Nessun figlio configurato nella famiglia. Chiedi al genitore di aggiungerti." |
| Encrypted family members | "Questa famiglia usa la sincronizzazione crittografata. Chiedi al genitore di aggiungerti dalle Impostazioni." |
| Code with confusable chars (0/O, 1/I) | Input field auto-converts: 0→O not needed since charset excludes them; input restricted to valid chars only |

## What Is NOT Changed

- `JoinFamily.jsx` — stays as-is for Settings page (handles encrypted case)
- `joinFamilyByCode()` in `sync.js` — reused without modification
- Invite code expiration — none (parent can regenerate manually)
- No new database tables or fields
- Steps 1, 2, 4–7 of the wizard — unchanged (4–7 are skipped for child flow)
- Settings page invite/join UI — unchanged

- **Error states:** invalid code, network error, no children, encrypted family
- **Member mapping:** verifies only `{ id, name, role, access_level, icon, color }` is passed (no internal fields)

- **Auth state:** verify `familyId`, `currentMember`, and `isSetupComplete` are set correctly
